# 0.6.2

A small release for Vite+ projects. The rule, the engine and the cache are 0.6.1's, so cached results carry over and nothing is measured again.

- **Commands that run in a Vite+ app.** When Vite+ runs the lint or the command (`vp lint`, `vp exec`), every command they print starts with `vp exec` in place of `npx`: the warning's `Run:`, the summary's, `--check`'s, the review page's and the job summary's.

  ```
  slimdeer: to see the 2 flagged images before and after on one page first, run: vp exec oxlint-plugin-slimdeer --review --flagged
  slimdeer: to shrink the 2 flagged images in place (lossy, so commit first), run: vp exec oxlint-plugin-slimdeer --flagged
  ```

  A new Vite+ app pins its package manager to an exact version (`devEngines.packageManager` in `package.json`), and an npm of another version then refuses every `npm` and `npx` command in it with `EBADDEVENGINES`. So the `npx` commands 0.6.1 printed failed there, while `vp exec` runs them.

  The plugin tells by `VP_USER_AGENT`, which Vite+ sets for what it runs. Outside Vite+ nothing changes: the commands start with `npx`.

  Tried on macOS in new apps made by `create-vite-plus` 1.7.0, one with npm and one with pnpm: `vp install -D oxlint-plugin-slimdeer`, `vp lint`, then the printed `--review --flagged` and `--flagged` commands as printed, and a second `vp lint` with no warnings.

- **The README's "Quick start with Vite+"** installs with `vp install -D oxlint-plugin-slimdeer` and lints with `vp lint`. Its `npm install` line failed in a new Vite+ app for the same reason.

The engine is unchanged: slimdeer 0.3.1, the same files as 0.6.0. [What 0.6.0 brought](https://github.com/lndgalante/oxlint-plugin-slimdeer/blob/main/docs/releases/0.6.0.md)
