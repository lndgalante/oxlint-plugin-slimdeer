# 0.6.4

If you lint a photo and then export a new version to the same path, `--flagged` now checks the bytes it reads against the content key the lint recorded. This protects the replacement even if it arrives after the command reads the flagged list, has the same file size, or you run with `--target 85`. The same check applies to `--review --flagged`, including WebP and AVIF reviews. For an older flagged list without content keys, run a fresh lint to record them.

- **Image references.** A `srcSet` candidate such as `/spring,sale.jpg 2x` keeps the comma in its filename. A remote URL such as `https://cdn.example/assets,/photo.jpg` no longer produces a warning for a local `/photo.jpg`.
- **Inline directives.** An image after an inline `/* eslint-enable slimdeer/compressible-image */` on the same line can warn and appear in `--flagged`. The same applies to Oxlint directives.
- **Next.js.** The re-encoding note follows the component imported from `next/image`. A parameter or local component that shadows its name gets the ordinary image warning.
- **WebP and AVIF copy names.** If `poster.png` and `poster.jpg` both qualify for `poster.webp`, check and review report both paths and exit 2. Other copies can still be reviewed and written. Review either source by path, or give one copy its own name with `-o`. Conflicts appear in `errors[]` in `--check --json`.
- **Disk I/O.** A cold same-format review writes previews only for images that clear both savings thresholds. In a lint of one source file with 100 references to the same warm image, reads of its cached measurement fell from 101 to 2.

This release uses the same slimdeer 0.3.1 engine and cache format as 0.6.3. It produces the same PNG, JPEG, WebP and AVIF bytes for the same input and target, and existing cached measurements carry over.
